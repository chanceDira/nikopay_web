### 2.2 Schema (public, RLS enabled on every table)

Aligned with `lib/settlement` statuses and chain ids (`polygon` | `base`).

| Table | Purpose |
|-------|---------|
| `profiles` | User row linked to `auth.users`; created on signup |
| `chains` | Polygon Amoy + Base Sepolia (seeded, active) |
| `tokens` | USDT placeholders per chain (`is_active = false` until P3) |
| `treasury_wallets` | Receive address placeholders (`is_active = false` until D4) |
| `fx_rates` | Rate, fee %, min USDT (sample row seeded) |
| `payment_intents` | Priced pay intent + status + treasury + MoMo fields |
| `chain_deposits` | Idempotent Transfer events (`chain_id`, `tx_hash`, `log_index`) |
| `intent_deposits` | Intent ↔ deposit match |
| `momo_transfers` | Disbursement attempts by UUID reference |
| `waitlist_entries` | Early access emails |

**RLS (v1)**
- Users: read own profile/intents; insert intents only as `awaiting_payment` for self  
- Authenticated: read chains, FX, active tokens/treasury  
- Admin: via `app_metadata.role = admin` (not editable `user_metadata`)  
- Status changes and worker writes: service role only  

`ledger_entries` deferred; not required for presentation happy path.
