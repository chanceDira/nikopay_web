## 2. Backend logic layer (main delivery)

### 2.1 Why this first

Settlement is the product. Before Postgres or routes, the backend needs a single source of truth for:

- What a payment intent is  
- Which status moves are legal (system vs admin)  
- When an unpaid intent expires  
- How a quote is priced (rate, fee, net FRW), always server-side  

That is `lib/settlement/`. Pure functions. No I/O. This is the first backend layer.

### 2.2 Module

| File | Role |
|------|------|
| `types.ts` | `PaymentStatus`, `ChainId`, `FxConfig`, `Quote`, `PaymentIntent` |
| `transitions.ts` | Allowed edges; `canTransition` / `allowedTransitions` |
| `intent-status.ts` | `transitionStatus` (Result), `assertTransition`, `IntentTransitionError` |
| `expiry.ts` | Expire only from `awaiting_payment` when past `expiresAt` |
| `quote.ts` | `createQuote` with validation. Never trust client prices |
| `index.ts` | Public barrel for APIs and jobs |

**Happy path (system)**

```text
awaiting_payment → detected → credited → payout_pending → paid
```

Also: `failed`, `expired`, `manual_review`.

**Admin-only:** retry `failed` → `payout_pending`; resolve `manual_review`; move `expired` into review.

**Quote:** positive USDT, FX min amount, positive rate, non-negative fee, valid expiry. Gross FRW = amount × rate. Fee and net computed in this layer.

**Expiry:** only `awaiting_payment` can expire. Credited or later statuses are not silently dropped.
